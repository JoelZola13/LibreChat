# Ultimate Documents App Context

Last updated: May 4, 2026

## Current Decision

Tiptap should be the primary writing surface and document data model for `/documents`. The native document source of truth should be Tiptap JSON plus derived plain text, metadata, versions, and exports.

Office editors should move into a supporting role. LibreOffice, Collabora, OnlyOffice, or Tiptap Conversion can remain available for import, export, preview, and fidelity checks, but day-to-day authoring should happen inside our own app.

## Why Tiptap

- Tiptap is a headless, framework-agnostic rich text editor built on ProseMirror, so we control the UI instead of fighting a bundled editor shell.
- Tiptap is extension-based, which fits the long-term goal: comments, track changes, templates, custom blocks, citations, approvals, AI assists, and collaboration can be added as first-class document behavior.
- The React path is straightforward: `@tiptap/react`, `@tiptap/pm`, and `@tiptap/starter-kit` are the core pieces, with extra extensions layered in for links, underline, alignment, highlights, task lists, tables, images, comments, and custom blocks.
- The Tiptap ecosystem includes Hocuspocus for Yjs-based collaboration and paid Pro/Conversion features for document conversion, commenting, versioning, and AI.

## Do We Still Need LibreOffice?

Not as the main documents tool.

For the goal of the ultimate documents app, LibreOffice is still useful as one possible conversion and fidelity backend. It can help with local/self-hosted DOCX, ODT, and PDF workflows, especially when we need privacy, offline operation, or a fallback that does not depend on a paid conversion API.

The better architecture is a pluggable conversion layer:

- Native authoring: Tiptap JSON in our app.
- Fast exports: HTML, Markdown, JSON, and text directly from Tiptap.
- Broad local ingestion: Docling for PDF, Office, HTML, Markdown, CSV, images, audio/video transcripts, structured XML, OCR, tables, figures, DocTags, and lossless Docling JSON.
- High-fidelity exports/imports: choose between Tiptap Conversion, LibreOffice/Collabora, OnlyOffice, Pandoc, Mammoth, Docling, or custom services based on file type and privacy needs.
- Print and legal-layout checks: use a render pipeline that can compare the app preview against exported PDF/DOCX output.

So the answer is: keep LibreOffice available, but do not make it the user-facing center of the documents experience.

## Docling Role

Docling should be the app's local ingestion and document intelligence layer. It converts many source formats into a unified `DoclingDocument`, then exports Markdown for editable Tiptap creation plus richer artifacts for future previews, search, citations, and analysis.

The first integration path is:

- Upload source file from `/documents`.
- Convert with Nanobot's `/api/documents/import/docling` route.
- Preserve Docling exports: Markdown, plain text, HTML, lossless JSON, DocTags, WebVTT when available, table assets, figure/page assets, and multimodal page records.
- Create the editable app document by passing Docling Markdown into the existing Markdown import endpoint.
- Keep LibreOffice as a fidelity/export fallback for office-layout edge cases rather than the primary authoring surface.

This gives us local parsing, OCR, tables, image extraction, and audio/video transcript ingestion without turning the user experience into an office-suite iframe.

## Product North Star

The app should feel like a serious document command center: fast writing, strong structure, easy reuse, collaborative review, and dependable exports.

Core surfaces:

- Document library with folders, templates, favorites, search, recents, trash, sharing, and version history.
- Tiptap editor with title editing, toolbar commands, links, lists, task lists, highlights, alignment, keyboard save, and track changes foundations.
- Review layer with comments, suggestions, accept/reject, approvals, assignments, and activity.
- Template system for grants, proposals, reports, letters, policies, invoices, scopes of work, meeting minutes, training materials, and case notes.
- AI side panel that can draft, rewrite, outline, cite sources, extract action items, produce summaries, and check funder or policy requirements.
- Import/export center for DOCX, PDF, ODT, Markdown, HTML, JSON, and text.
- Version and provenance layer that stores snapshots, change notes, authorship, source references, and generated content disclosures.

## Architecture Direction

Use Tiptap JSON as the canonical editable content. Store these derived fields alongside it:

- `content`: Tiptap JSON.
- `content_text`: plain text for search, previews, AI context, and word counts.
- `metadata`: page settings, template id, source ids, export preferences, and approval state.
- `versions`: immutable snapshots with author, timestamp, change type, and change note.
- `suggestions`: track-changes records that can be accepted or rejected.
- `comments`: anchored to document, selection, or block positions.

Conversion should be asynchronous where possible. Large DOCX/PDF jobs should run as background tasks with status, logs, and downloadable artifacts.
